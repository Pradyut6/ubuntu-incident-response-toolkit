# INC-003 — Nginx file permission denied

**Status:** NOT RUN — instructions for a future isolated Ubuntu 24.04 VM exercise, not evidence of actual incident resolution.  
**Severity (simulated):** medium  
**Service profile:** `nginx`  
**Failure method:** Manual opt-in fault injection only in a disposable VM.

> **DANGER:** Never execute scenario steps in WSL, on your Windows host, or on a production/customer/school machine. Verify VirtualBox guest console access, NAT networking and the `CLEAN-BASELINE` VM snapshot first. Read every command before executing it. Only work with deliberately named `uir-*` resources where possible.

## Reported symptom (simulated)

A disposable web page returns HTTP 403.

## Hypothesis / controlled fault

Remove read permission from a dedicated test document only.

## Preflight and incident creation

Check the VM is disposable, restore instructions are available, and prerequisite services are healthy. From repository root:

```bash
./bin/uir doctor
./bin/uir init
./bin/uir incident create --id INC-003 --service nginx --severity medium --summary 'Nginx file permission denied'
```

If the incident ID already exists, create a new training ID and adjust commands (existing records are never overwritten). None of the above commands causes the failure.

## Stage the controlled failure

```bash
# Precondition: do not overwrite a pre-existing unit or test fixture.
[[ ! -e /etc/nginx/conf.d/uir-003.conf && ! -e /var/www/uir-003 ]] || { echo "Lab fixture exists; abort"; exit 1; }
sudo mkdir -p /var/www/uir-003
printf 'uir-003-ok\n' | sudo tee /var/www/uir-003/index.html >/dev/null
printf 'server { listen 8083; server_name _; root /var/www/uir-003; }\n' | sudo tee /etc/nginx/conf.d/uir-003.conf >/dev/null
sudo chmod 000 /var/www/uir-003/index.html
sudo nginx -t && sudo systemctl reload nginx
curl -i --max-time 5 http://127.0.0.1:8083/
```

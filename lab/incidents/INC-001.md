# INC-001 — Custom systemd unit fails to start

**Status:** NOT RUN — instructions for a future isolated Ubuntu 24.04 VM exercise, not evidence of actual incident resolution.  
**Severity (simulated):** medium  
**Service profile:** `uir-training-001`  
**Failure method:** Manual opt-in fault injection only in a disposable VM.

> **DANGER:** Never execute scenario steps in WSL, on your Windows host, or on a production/customer/school machine. Verify VirtualBox guest console access, NAT networking and the `CLEAN-BASELINE` VM snapshot first. Read every command before executing it. Only work with deliberately named `uir-*` resources where possible.

## Reported symptom (simulated)

A disposable training unit exits before serving its intended process.

## Hypothesis / controlled fault

Wrong ExecStart binary in a dedicated /etc/systemd/system/uir-training-001.service.

## Preflight and incident creation

Check the VM is disposable, restore instructions are available, and prerequisite services are healthy. From repository root:

```bash
./bin/uir doctor
./bin/uir init
./bin/uir incident create --id INC-001 --service uir-training-001 --severity medium --summary 'Custom systemd unit fails to start'
```

If the incident ID already exists, create a new training ID and adjust commands (existing records are never overwritten). None of the above commands causes the failure.

## Stage the controlled failure

```bash
# Precondition: do not overwrite a pre-existing unit or test fixture.
[[ ! -e /etc/systemd/system/uir-training-001.service ]] || { echo "Training unit already exists; abort"; exit 1; }
sudo tee /etc/systemd/system/uir-training-001.service >/dev/null <<'UNIT'
[Unit]
Description=UIR disposable failure scenario 001
[Service]
Type=simple
ExecStart=/usr/bin/uir-intentionally-missing-executable
[Install]
WantedBy=multi-user.target
UNIT
sudo systemctl daemon-reload
sudo systemctl start uir-training-001.service || true
```

## Read-only investigation

```bash
systemctl status uir-training-001.service --no-pager
journalctl -u uir-training-001.service -n 30 --no-pager
systemctl show uir-training-001.service -p ExecStart -p Result
```

Capture a **before** snapshot when the symptom is present:

```bash
./bin/uir capture --incident INC-001 --phase before --minutes 15
./bin/uir incident note --id INC-001 --kind hypothesis --text 'Record a hypothesis supported by actual evidence'
```

**Evidence caveat:** The current CLI service collector profiles are deliberately narrow. ## Repair / restore service

```bash
sudo sed -i 's@/usr/bin/uir-intentionally-missing-executable@/usr/bin/sleep infinity@' /etc/systemd/system/uir-training-001.service
sudo systemctl daemon-reload
sudo systemctl start uir-training-001.service
systemctl is-active uir-training-001.service
```

```bash
sudo systemctl stop uir-training-001.service || true
sudo rm -f /etc/systemd/system/uir-training-001.service
sudo systemctl daemon-reload
```

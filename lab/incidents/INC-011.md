# INC-011 — Service events missing from expected journal filter

**Status:** NOT RUN — instructions for a future isolated Ubuntu 24.04 VM exercise, not evidence of actual incident resolution.  
**Severity (simulated):** low  
**Service profile:** `uir-training-011`  
**Failure method:** Manual opt-in fault injection only in a disposable VM.

> **DANGER:** Never execute scenario steps in WSL, on your Windows host, or on a production/customer/school machine. Verify VirtualBox guest console access, NAT networking and the `CLEAN-BASELINE` VM snapshot first. Read every command before executing it. Only work with deliberately named `uir-*` resources where possible.

## Reported symptom (simulated)

A technician cannot find known test events in a service unit journal.

## Hypothesis / controlled fault

A synthetic tagged event logged with logger rather than to the unit.

## Preflight and incident creation

Check the VM is disposable, restore instructions are available, and prerequisite services are healthy. From repository root:

```bash
./bin/uir doctor
./bin/uir init
./bin/uir incident create --id INC-011 --service uir-training-011 --severity low --summary 'Service events missing from expected journal filter'
```

If the incident ID already exists, create a new training ID and adjust commands (existing records are never overwritten). None of the above commands causes the failure.

## Stage the controlled failure

```bash
logger -t uir-training-011 -p user.err 'UIR INC-011 synthetic error event'
journalctl -u uir-training-011.service -n 10 --no-pager
```

## Read-only investigation

```bash
journalctl -u uir-training-011.service -n 20 --no-pager
journalctl -t uir-training-011 -n 20 --no-pager
journalctl --list-boots
```

Capture a **before** snapshot when the symptom is present:

```bash
./bin/uir capture --incident INC-011 --phase before --minutes 15
./bin/uir incident note --id INC-011 --kind hypothesis --text 'Record a hypothesis supported by actual evidence'
```

**Evidence caveat:** The current CLI service collector profiles are deliberately narrow. An application-level error, package issue, separate test port, DNS fixture or firewall fixture may NOT change the service-active field; use the read-only manual checks above and record their real observed results in the case study. Do not claim the toolkit proved an outcome it did not measure.

## Repair / restore service

```bash

journalctl --since '5 minutes ago' --no-pager | grep -F 'UIR INC-011' || true
```

# INC-002 — SSH configuration prevents a new connection

**Status:** NOT RUN — instructions for a future isolated Ubuntu 24.04 VM exercise, not evidence of actual incident resolution.  
**Severity (simulated):** high  
**Service profile:** `ssh`  
**Failure method:** Manual opt-in fault injection only in a disposable VM.

> **DANGER:** Never execute scenario steps in WSL, on your Windows host, or on a production/customer/school machine. Verify VirtualBox guest console access, NAT networking and the `CLEAN-BASELINE` VM snapshot first. Read every command before executing it. Only work with deliberately named `uir-*` resources where possible.

## Reported symptom (simulated)

A simulated user cannot connect to a lab SSH endpoint.

## Hypothesis / controlled fault

A deliberately invalid **secondary** sshd configuration; leave the primary SSH server intact.

## Preflight and incident creation

Check the VM is disposable, restore instructions are available, and prerequisite services are healthy. From repository root:

```bash
./bin/uir doctor
./bin/uir init
./bin/uir incident create --id INC-002 --service ssh --severity high --summary 'SSH configuration prevents a new connection'
```

If the incident ID already exists, create a new training ID and adjust commands (existing records are never overwritten). None of the above commands causes the failure.

## Stage the controlled failure

```bash
cat > "$HOME/uir-ssh-002.conf" <<'CONF'
Port not-a-port
ListenAddress 127.0.0.1
HostKey /etc/ssh/ssh_host_ed25519_key
PidFile /tmp/uir-ssh-002.pid
CONF
sudo /usr/sbin/sshd -t -f "$HOME/uir-ssh-002.conf" || true
```

## Read-only investigation

```bash
sudo /usr/sbin/sshd -t -f "$HOME/uir-ssh-002.conf"
systemctl status ssh.socket ssh.service --no-pager
sudo ss -lntp | grep -E ':22|:2222' || true
```

./bin/uir incident note --id INC-002 --kind hypothesis --text 'Record a hypothesis supported by actual evidence'

## Repair / restore service

```bash
sed -i 's/Port not-a-port/Port 2222/' "$HOME/uir-ssh-002.conf"
sudo /usr/sbin/sshd -t -f "$HOME/uir-ssh-002.conf"
# Optional: only if console and firewall checks are complete:
# sudo /usr/sbin/sshd -D -f "$HOME/uir-ssh-002.conf"
```

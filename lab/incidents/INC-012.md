# INC-012 — Service dependency prevents startup

**Status:** NOT RUN — instructions for a future isolated Ubuntu 24.04 VM exercise, not evidence of actual incident resolution.  
**Severity (simulated):** medium  
**Service profile:** `uir-training-012`  
**Failure method:** Manual opt-in fault injection only in a disposable VM.

> **DANGER:** Never execute scenario steps in WSL, on your Windows host, or on a production/customer/school machine. Verify VirtualBox guest console access, NAT networking and the `CLEAN-BASELINE` VM snapshot first. Read every command before executing it. Only work with deliberately named `uir-*` resources where possible.

## Reported symptom (simulated)

Training application cannot start while its required dependency is absent.

## Hypothesis / controlled fault

Two isolated systemd training units with Requires/After; only test services are affected.

## Preflight and incident creation

Check the VM is disposable, restore instructions are available, and prerequisite services are healthy. From repository root:

```bash
./bin/uir doctor
./bin/uir init
./bin/uir incident create --id INC-012 --service uir-training-012 --severity medium --summary 'Service dependency prevents startup'
```

If the incident ID already exists, create a new training ID and adjust commands (existing records are never overwritten). None of the above commands causes the failure.

## Stage the controlled failure

```bash
# Precondition: do not overwrite a pre-existing unit or test fixture.
[[ ! -e /etc/systemd/system/uir-training-012.service && ! -e /etc/systemd/system/uir-training-dependency.service ]] || { echo "Training unit already exists; abort"; exit 1; }
sudo tee /etc/systemd/system/uir-training-012.service >/dev/null <<'UNIT'
[Unit]
Description=UIR dependency practice application
Requires=uir-training-dependency.service
After=uir-training-dependency.service
[Service]
Type=simple
ExecStart=/usr/bin/sleep infinity
UNIT
sudo systemctl daemon-reload
sudo systemctl start uir-training-012.service || true
```

```bash
systemctl list-dependencies uir-training-012.service

journalctl -u uir-training-012.service -n 40 --no-pager
```

## Repair / restore service

```bash
sudo tee /etc/systemd/system/uir-training-dependency.service >/dev/null <<'UNIT'
[Unit]
Description=UIR dependency practice prerequisite
[Service]
Type=simple
ExecStart=/usr/bin/sleep infinity
UNIT
sudo systemctl daemon-reload
sudo systemctl start uir-training-dependency.service
sudo systemctl start uir-training-012.service
systemctl is-active uir-training-012.service
```

## Lab cleanup (always perform)

```bash
sudo systemctl stop uir-training-012.service uir-training-dependency.service 2>/dev/null || true
sudo rm -f /etc/systemd/system/uir-training-012.service /etc/systemd/system/uir-training-dependency.service
sudo systemctl daemon-reload
```
